## 1. 实验要回答的问题

当前默认是 **RRF k=60、dense:bm25 等权**（`Config.RRF_K=60`，`reciprocal_rank_fusion` 无权重参数）。
这两个值都来自**惯例/文献默认**，没有在本项目语料上验证过。Step 2 之前的一次审计性实验显示：

| 配置（等预算 20，带过滤） | R@5 |
| --- | --- |
| RRF k=60 等权（当前默认） | 0.4248 |
| RRF k=10 等权 | 0.4387 |
| RRF 加权 dense=1, bm25=3 | 0.4427 |

→ 参数**确实敏感**（差距 > 0.01）。但那次是**临时脚本**跑出来的，本次要用**正式评测路径**确认，
并回答：**为了这点差距引入加权是否值得**（评审原则：差距 <1% 就保持简单）。

## 2. 实验设计

### 2.1 网格（12 格）

```text
RRF_K ∈ {10, 30, 60, 100}
weights (w_dense, w_bm25) ∈ {(1,1), (1,2), (1,3)}
合计 12 格（4 × 3）
```

**加权公式**（与现有一致，仅加系数）：

```text
score(doc) = Σ_r  w_r / (k + rank_r(doc))        r ∈ {dense, bm25}
```

> 说明：加权 RRF 具有**尺度不变性**——`(1,2)` 与 `(2,4)` 等价，因此权重网格只需覆盖**比例**（1:1 / 1:2 / 1:3），
> 不必枚举绝对值；这也是不引入"动态权重"的原因之一（收益不可解释、复杂度上升）。

### 2.2 冻结的协议（**完全不动**）

```text
candidate-k = 20      （dense 取 20、BM25 取 20）
fusion-k    = 20      （RRF 后保留 20）
final-k     = 20      （计分与返回；四配置一致）
BM25_WINDOW = 0       （Step 2 修复后的默认）
指标        recall@5/10、precision@5/10、mrr、ndcg@5/10、unique docs、中位延迟
评测集      data/eval/retrieval_eval.json（36 题，sha256[:16]=971db9cafd93772c）—— 不改
```

### 2.3 两种设定都跑

| 设定 | 角色 | 理由 |
| --- | --- | --- |
| **带过滤（filtered）** | **主判据** | 22/36 题带 stock_code、35/36 带 doc_type —— 这是 Agent 的真实用法 |
| 不带过滤（unfiltered） | 稳健性校验 | 防止参数只在过滤场景下"过拟合"；且 Step 2 已证明两设定行为不同 |

### 2.4 成本控制：候选只算一次

关键设计：**每题的 dense top-20 与 BM25 top-20 只计算一次**，12 格参数只是在这两份候选上做纯 Python 融合 + 计分。

```text
成本 ≈ 一次常规评测的检索开销（模型加载 ~20s + 36 题 × (dense+bm25)）
       + 12 格 × 36 题的融合与计分（毫秒级）
       + reranker 短名单校验（见 2.5）
```

因此"跑 12 格"与"跑 1 格"的耗时几乎相同 —— 这是本实验能覆盖完整网格而不是只挑几格的前提。

### 2.5 reranker 的校验方式（短名单，而非全网格）

RRF 参数会同时影响两个下游：① `hybrid`（无 rerank）的最终列表；② `hybrid+rerank` 的**候选集**。
为控制成本与结论清晰度：

- **主分析**：全网格在 `hybrid`（无 rerank）上做；
- **校验**：对**短名单**（默认格 + 最优格 + 最优格的邻域共 3~4 格）额外跑 `hybrid+rerank`，
  确认"选中的参数不会伤害最终生产配置"；
- 不在全网格上跑 rerank（每次 ~0.4s/题 × 36 × 12 ≈ 3 分钟，收益不匹配）。

### 2.6 稳定性检查（防止在 36 题上过拟合）

- **2-fold 交叉**：按题号奇偶拆成两折（各 18 题），分别在两折上算 R@5；
- 判据：选中参数需在**两折上都不劣于默认格**（容差 ±0.02，因每折仅 18 题，单题即 0.056）；
- 若某参数只在整体上领先、但在一折上明显落后 → 判为**不稳定**，不作为默认值。

## 3. 决策规则（写死，避免事后挑参数）

按顺序判定，**第一个满足的即为结论**：

1. **简单优先**：若最优格与默认格 `(k=60, 1:1)` 的 filtered R@5 差距 **< 0.01**，
   → **保持默认 k=60 等权**，并在文档中写明"调参未带来稳定收益"；
2. 若差距 ≥ 0.01，但候选格的 **2-fold 稳定性不通过** → 同样保持默认；
3. 若差距 ≥ 0.01 **且** 两折稳定性通过 **且** 在 unfiltered 上不劣于默认（容差 0.01）
   **且** 短名单 rerank 校验不劣化 →
   → 采纳该格（优先选**权重更简单**的：等权 > 加权；k 值取网格内**中间值**而非极值，避免边界效应）；
4. 任何情况下**不引入**在线/动态权重、不引入 per-intent 权重、不引入 query 类型分类后再选参。

> 规则 4 是硬约束：本项目定位是"可解释的工程化作品"，**参数必须能一句话讲清**，
> "根据 query 类型动态调权"在本规模下无法验证收益，反而增加面试时被追问翻车的面。

## 6. 风险与局限（会写进文档）

| 项 | 说明 |
| --- | --- |
| **样本量小** | 36 题；单题翻转即 0.0278 —— 因此设 <0.01 的"简单优先"阈值与 2-fold 检查；结论表述为"经验参数" |
| **标签偏词面** | 标签由标题关键词生成，对 BM25 天然略有利（Batch 3 才会定量剔除），这可能**系统性偏向更高的 bm25 权重** —— 因此即使加权胜出，也要标注该偏差 |
| **网格边界** | k=10 与 k=100 是边界值；若最优落在边界，应视为"网格外可能更好"的信号，**不因此扩大网格**（避免无限调参），而是记录在局限中 |
| **语料/模型变更** | 参数结论绑定当前语料（109,554 chunks）与当前模型（bge-m3 + bge-reranker-v2-m3）；换 embedding 或语料需重跑本实验 |
| **无显著性检验** | 样本量不支持；不做 p 值，只做折半稳定性与效应量（差距是否 > 1%） |
