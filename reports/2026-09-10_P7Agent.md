### 受控设计要点

- **确定性优先**：意图、股票解析、工具计划都是规则驱动；LLM 只在"规则无法判断意图"和"是否需要**追加**工具调用"两处介入——它**不能跳过基线计划**；
- **硬边界**：工具白名单（越权调用记录为 `ToolNotAllowed`）、单工具超时（→ `ToolTimeout`）、最大循环次数、最大工具调用数；
- **失败不炸循环**：`call_tool` 现在连**非 QuantError 的意外异常**（缺 BM25 索引、缺模型文件等）也转为结构化错误，Agent 循环始终能收尾；
- **证据校验门**：量化类意图若没有量化工具结果 → `evidence_ok=False`，报告必须写明数据缺失；证据缺 metadata、知识库零命中，都会写进 `validator_notes`；
- **报告只能看到工具输出**：`report_generator` 的 prompt 里只有工具结果 JSON，没有预置常识。

## 3. 真实端到端验证（DeepSeek + 真检索栈）

```text
$ python scripts/ask.py "分析一下京东方A"
model=deepseek-v4-flash key_set=True
intent=stock_analysis (source=rule) stocks=['000725']        ← 全角/半角归一化生效
plan=['get_stock_profile','predict_stock','get_stock_factors','search_financial_knowledge']
  tool get_stock_profile ok=True / predict_stock ok=True / get_stock_factors ok=True
  tool search_financial_knowledge ok=True (5 条证据)
evidence=5 evidence_ok=True elapsed=33.8s
```

**生成报告的质量（真实输出摘录）**：

- 开头主动声明 **"量化基准日 2026-06-24 早于检索到的最新消息 2026-08-31，两者不是同一时点，不能拼接为『当前状态』"** —— 这是数据时效性风险的自觉处理；
- 逐条区分「数据事实 / 模型结果 / 基于证据的推断」，并列出**数据缺失**清单（无估值、无财务、无资金流…）；
- 明确写出 `strong_prob` 是弱信号、**"不得解读为上涨概率 30.7%"**；
- 指出模型预测（-3.07%）与同基准日动量因子（ret_5d +16.07%）**方向不一致**，并明确声明"工具未提供解释，我不做补充推断"；
- 每条证据都带来源与日期（eastmoney / cninfo + URL）。

第二个查询 `现在评分最高的5只股票`：`intent=stock_ranking`、`plan=[rank_stocks]`、25.0s；
报告如实指出"工具实返回 Top 10，问题要 5 只"，以 Top 5 为主体并列出其余。
