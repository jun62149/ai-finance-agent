用户执行 `build_embeddings.py` 时暴露出两件事：

   全库约 **9.5 万 chunk**。
2. **Qdrant 本地模式告警**：
   `Local mode is not recommended for collections with more than 20,000 points`
   —— 当前规模是官方建议上限的 4~5 倍。

## 2. 本地模式的两个实测坑（都已在代码里处理/记录）

| 坑 | 表现 | 处理 |
| --- | --- | --- |
| **单进程文件锁** | 用户嵌入任务运行期间，任何其它进程打开 `data/qdrant` 都会失败：`Storage folder ... is already accessed by another instance of Qdrant client`（本次 dry-run 校验实测） | 这正是必须切服务端的直接证据；迁移脚本、API 都要求服务端 |
| **delete+create 复活旧点** | `delete_collection` + `create_collection` 后 `count()` 仍返回旧点数（qdrant-client 1.19，已复现） | `ensure_collection(recreate=True)` 之后追加显式 `purge()`（filter 删除），并加回归测试 |

> 结论：本地模式可用于开发期快速跑通，但不能作为 API/Agent 阶段的存储——**必须迁移到 Qdrant 服务**。

## 4. 环境备注（用户侧）

- **torch 装成了 CPU 版**导致 `Torch not compiled with CUDA enabled`，我的 device 回退逻辑按预期打印告警并落到 CPU（3.3 chunks/s）。
  修复：停进程 → `pip uninstall -y torch` → `pip install torch --index-url https://download.pytorch.org/whl/cu126` → 校验 `torch.cuda.is_available()`。
  已嵌入的部分不会白跑（版本一致会跳过）。
- Docker registry 镜像加速已配置（ustc / 腾讯云 / daocloud），`docker pull qdrant/qdrant` 有镜像可用；本机尚未有 qdrant 镜像。
- 精度一致性提醒：同版本内 CPU/GPU(fP32) 混用没问题；若改用 fp16 提速，应 bump `EMBEDDING_VERSION` 后重建。
