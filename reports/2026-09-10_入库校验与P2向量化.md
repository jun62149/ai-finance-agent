### 1.1 校验中发现并修复的 BUG：cninfo 分页静默截断 ⚠️

现象：公告日期范围只有 **2026-03-26 ~ 2026-09-12（约 6 个月）**，且每只股票都恰好 27~34 篇。

根因（实测确认）：cninfo `hisAnnouncement/query` **每页最多 30 条**；当传入
`pageSize>30`（原默认 50）时，服务端**忽略 `pageNum`**，翻到第 2 页仍返回第 1 页内容
（size=50 时 page1==page2；size=30 时翻页正常）。于是每只股票只拿到最新约 30 篇。
另：`totalpages` 字段不可信（报 3 页实际有 4 页）。

修复（`01da4f0`）：

- `page_size` 钳制到 `CNINFO_MAX_PAGE_SIZE=30`（CLI 默认也改为 30）；
- 按 `announcementId` 对分页去重；某页"无新增"即判定服务端忽略 pageNum 并干净退出；
- 停止条件改用 `hasMore` / `totalRecordNum`，不再用 `totalpages`；
- 新增 2 个回归测试（钳制 + 重复页止损）。

修复后实测 600519：**94 条**（原来 30 条），跨度 2025-10-28 ~ 2026-08-15，`art_code` 全部唯一。

**⇒ 需要你重跑一次公告抓取补齐**（见第 4 节第 1 步）。预计公告量会从 963 增至约
2,500~3,000 篇、chunks 从 22k 增至约 60k~70k。

## 2. P2 实现内容（dense retrieval）

| 文件 | 说明 |
| --- | --- |
| `app/rag/embedding.py` | `Embedder`：惰性导入 sentence-transformers（不引入 torch 也能跑其它链路）、device 失败自动回落 CPU 并打印告警、向量 L2 归一化、版本号来自 `EMBEDDING_VERSION` |
| `app/rag/vector_store.py` | `ChunkVectorStore`：Qdrant **本地 path 模式**（与 Docker 服务版 API 同构，`QDRANT_URL` 一改即切服务）；payload 只存元数据，支持 `stock_code`/`doc_type` 过滤 |
| `app/rag/indexing.py` | `build_embeddings`（可续跑：**先 upsert 成功再回写 SQLite 版本**，point id = SQLite chunk id，天然幂等）+ `semantic_search`（命中后回表取正文） |
| `app/db.py` | `fetch_chunks_for_embedding` / `set_chunks_embedding_version` / `embedding_stats` / `fetch_chunk_contents` |
| `app/config.py` | `EMBEDDING_MODEL/DEVICE/BATCH_SIZE/VERSION/DIM`、`QDRANT_PATH/COLLECTION/URL` |
| `scripts/build_embeddings.py` | 建向量入库；`--limit/--doc-type/--batch-size/--device/--recreate`；结束打印 pending，0 即完成 |
| `scripts/search_chunks.py` | query → top-k chunk（含 score / 标题 / 日期 / 来源 / url / 正文预览），即 P2 最小链路 |
| `tests/unit/test_indexing.py` | 7 个测试：真实 Qdrant 本地库 + 确定性假向量 |

### 关键设计决策

- **Qdrant 只存元数据，正文以 SQLite 为唯一真源**：命中后按 point_id 回表取 content，
  避免两库漂移（也是后续 RAG Tool 直接可用的形态）。
- **版本一致性**：`EMBEDDING_VERSION` 变化即视为需重嵌（`embedding_version != version` 也算 pending），
  保证新旧向量永不混库。
- **维度自检**：模型输出维度与 collection 不一致时显式报错并提示设置 `EMBEDDING_DIM`，不静默写入。
