### 关键设计

1. **工具与 API 语义永不漂移**：量化工具调用的是 `stock_service` / `prediction_service`，
   同一份错误码；测试里显式断言"工具层不会发明另一套错误词汇"。
2. **结构化错误边界**：`call_tool()` 返回 `{"ok": true, "result": ...}` 或
   `{"ok": false, "error": {"code": ..., "message": ...}}`——Agent 循环里**永远不抛异常、也永远拿不到假数据**。
3. **证据可信性硬约束**：返回前逐条校验 `chunk_id/document_id/stock_code/doc_type/title/source/publish_time/url`，
   缺任何一项抛 `EvidenceMetadataMissing`（铁律：RAG 输出必须可追溯）。
4. **无危险工具**：注册表内不存在 SQL / Shell / 文件工具，并有测试守住这一条。

## 2. 本轮附带解决的能力缺口：时间过滤（`days`）

设计文档 §12 的工具签名含 `days`，但 Qdrant 只能对**数值/日期**字段做区间过滤，而 payload 里
`publish_time` 是字符串 → 无法直接过滤。处理：

- 新增 `publish_ts`（epoch 秒）payload 字段 + `stock_code`/`doc_type`/`publish_ts` **payload 索引**；
- `scripts/backfill_publish_ts.py` 原地回填 **109,554 点 / 282s**（0 条时间解析失败，**未重新嵌入**）；
- Dense 走 Qdrant 数值 `Range` 过滤；BM25 因 bm25s 不支持过滤，改为**检索后按日期过滤**（有过滤时自动扩大候选窗口）；
- 检索层与工具层统一暴露 `days` / `date_from` / `date_to`。

实测（真实服务端）：
```
POST /api/rag/search {query: 京东方A 回购股份 实施结果, stock_code: 000725, doc_type: announcement, days: 400, top_k: 2}
→ 200, count=2, reranked=true
  [1] 2026-05-30 dense=0.731 bm25=14.50 rrf=0.0328 rerank=0.9993
      url http://static.cninfo.com.cn/finalpage/2026-05-30/1225338046.PDF
      citation: 关于回购股份方案实施完毕暨回购实施结果的公告（cninfo，2026-05-30）
```

## 4. 已知代价 / 待办

1. **冷启动慢**：首次请求含模型加载（实测 dense 13.5s + rerank 6.3s）。热态为 30ms + 350ms。
   P8 部署时应在 API 启动钩子里预加载（`RAG_PRELOAD=1`），本轮未做以免拖慢测试。
2. BM25 的元数据过滤是**检索后过滤**（bm25s 无过滤能力），极端过滤条件下召回会受限；
   后续若评测显示影响明显，可换成 Qdrant 稀疏向量（原生支持过滤）。
3. `days` 的语义是"相对今天"，评测/回测场景请用 `date_from/date_to` 显式指定。
