两份快照均无 `.git`。快照 B 多出：过拟合诊断、训练/测试双指标、TopN 可选、板块与流动性过滤、回测含费用前口径、数据采集进度回调、`clear_table` 等。

### B. XGBoost 模型入口

- 命令行入口：`scripts/train_model.py` → `app/services/model_service.py::train_models()`
- 预测入口：`model_service.predict_latest()`（全市场最新因子 → 预测 → 综合评分 → 落库）
- 回测入口：`model_service.run_backtest()`（测试区间按 5 交易日调仓，B 版支持 TopN/是否含双创）
- 双模型：`XGBRegressor`（预测 5 日超额收益）+ `XGBClassifier`（强势股概率），CUDA 失败自动回退 CPU。
- 综合评分（A 版）：`score = pred_return*100*0.55 + strong_prob*40 - risk*12`；B 版权重已调整（0.75/15/10）。

### C. 因子计算入口

- `scripts/rebuild_factors.py` → `factor_service.rebuild_factors()` / `build_factor_frame()`
- 11 个输入因子：`ret_5d/10d/20d`、`ma5_bias/ma20_bias`、`volatility_10d/20d`、`volume_ratio_5d`、`amount_mean_20d`、`turnover_mean_20d`、`drawdown_20d`
- 标签：`future_excess_return_5d`（相对全市场均值超额）、`strong_label`（当日收益排名前 30%）
- B 版新增：训练池过滤（上市 ≥120 日、20 日均额 ≥5000 万、非 ST）、单股最少 60 个观测。

### D. 数据库结构（SQLite）

现有 5 张表：`stock_basic`、`stock_daily`、`factor_values`、`prediction_result`、`backtest_result`。B 版通过迁移在 `prediction_result` 加 `board` 列、在 `backtest_result` 加费用前收益/TopN/含双创列。

实测数据规模（2026-09-07）：

| 库 | stock_basic | stock_daily | factor_values | prediction_result | backtest_result |
| --- | --- | --- | --- | --- | --- |
| A（workspace，241MB） | 5,208 | 1,543,560（1043 只 × 2020-01-02~2026-06-24） | 30,710（仅 20 只股票） | 20 | 309 |
| B（work，49KB） | 0 | 0 | 0 | 0 | 0 |

说明：A 库有 1043 只股票的完整历史，但因子表只重算过 20 只（小样本演示）；要做 Agent 的“全市场选股”需对已有行情**重新重建因子**（1.5M 行，预计数分钟~十几分钟）。B 库已清空但保留全 A 训练出的模型。

### E. Flask / API 入口

- `run.py` 启动 Flask；页面：登录、仪表盘、数据、因子、模型、选股、个股详情、回测、日志。
- 任务均为 `POST /tasks/*`（更新数据、重建因子、训练、预测、回测），**只有页面跳转，没有对外 JSON API**。
- 登录硬编码 `admin/123456`，`SECRET_KEY` 硬编码——Agent 项目必须环境变量化。

结论：原系统不需要把 Flask 替换掉，但新系统的 AI 层应新建 FastAPI，原有量化能力通过 service 函数或轻量适配层被调用；Flask 可作为“管理后台”保留在毕设目录。

2. `factor_service.build_factor_frame()`：因子与标签逻辑，语义明确。

4. `filter_service`（B 版）：`stock_board`、`add_pool_flags`、`apply_model_pool_filter` —— 板块/流动性/上市时长逻辑可直接服务“股票池过滤”工具。

### I. 需要重构/改造的部分

1. **服务层函数没有“稳定契约”**：多数函数直接读写 pandas DataFrame / 全局 Config，没有 Pydantic schema。Agent 工具层需要稳定输入输出，第一步应抽出 `get_stock_factors(code)`、`predict_stock(code)`、`rank_stocks(top_n)` 三个稳定接口。
2. **“按日期查询”能力缺失**：现有预测只有“最新因子快照”，没有 as-of（指定交易日）的历史因子/预测查询；Agent 和评测都需要时间参数。
3. **空库假数据兜底**：`dashboard_service`/`sample_data` 在空库时返回编造的 demo 数据，对网页演示是好意，但若被 Agent/API 层误用会直接产生“幻觉”。新 API 层必须显式报错或返回空结果，绝不走 demo 兜底。
4. **配置硬编码**：登录口令、SECRET_KEY、数据库路径等需 `.env` 化。
5. **股票代码归一化逻辑分散**在 data_source 与 filter 两处，应统一为一个模块。
6. **无版本管理与测试**：两份代码靠复制演进，且没有单测；新仓库必须 git init + 关键单测。
7. **语料/向量库基础设施完全空白**：documents、chunks、embedding、检索、评测均为 0，需按设计文档从零建设。
8. 数据时效：当前 DB 截止 2026-06-24，如需“最新预测”需先增量更新。

### J. 风险点

- 代码/数据快照漂移（A、B 不一致）——先统一基线再开发。
- 无 git，任何大改都不可回滚——开发前必须版本管理 + 备份。
- B 版分类模型 recall≈0，量化输出质量需如实表述。
- 免费数据源（AkShare/BaoStock）不稳定，全市场抓取耗时长——新闻/公告抓取要小步验证。
- 数据库 241MB 属大文件，不能进 git，需 gitignore + 独立备份。
- 金融内容合规：所有输出需声明“模型分析而非投资建议”，不提供确定性承诺。
- Docker Desktop 未启动（CLI 已装 29.6.2，但 daemon 未运行）；Qdrant 容器化方案需要启动 Docker，或 MVP 先用本地嵌入式向量库。
- API Key/日志隐私：`.env`、`.gitignore`、日志脱敏必须在第一阶段落地。

## 六、二次开发迁移计划（对齐设计文档 §25/§26/§35）

### 目标与铁律（来自开发文档 §0）

- LLM 不负责量化计算，只负责理解、路由、工具调用、证据组织与解释。
- RAG 输出必须保留 `source_id / title / date / source / url`。
- Agent 必须有工具边界、超时、结构化错误与最大循环次数。
- API Key 全部 `.env`，日志不落敏感内容。
- 每个阶段先跑通最小链路再加功能，小步提交可回滚。

### 建议仓库结构（依据文档 §4，从原系统迁移内核）

```text
ai-finance-agent/
├── app/
│   ├── main.py / api/        # FastAPI
│   ├── agents/               # LangGraph StateGraph + prompts + policies
│   ├── tools/                # quant_tools / rag_tools
│   ├── services/             # stock/prediction/retrieval/report 服务
│   ├── rag/                  # ingestion/cleaner/chunker/embedding/bm25/hybrid/reranker
│   ├── quant/                # 从原系统迁移：features/predictor/scoring/ranking
│   └── db/ + schemas/
├── data/{raw,cleaned,eval}/
├── scripts/                  # ingest_news / ingest_announcements / evaluate_retrieval
├── tests/{unit,integration,eval}/
├── frontend/
├── models/                   # 从原系统复制 pkl + 新增 embedding 模型缓存
├── docker/ + docker-compose.yml + .env.example
└── README.md
```

原系统迁移原则：`quant/` 只搬纯计算逻辑（因子、预测、评分、排名），读库走统一 service；Flask 页面不搬入新仓库（可作为 legacy 工具保留在原目录），新 UI 用轻量前端对接 FastAPI。

### 关键实现决策（依据文档 §33，补充落地细节）

| 决策点 | 建议 |
| --- | --- |
| Agent 编排 | LangGraph 确定性节点 + 受控 Agent：`query_analyzer → stock_resolver → task_planner → tool_execution_loop → evidence_validator → report_generator`，最大循环 4~8 次 |
| 向量库 | MVP 可用 Qdrant 本地模式/Docker；若 Docker daemon 不启动，先降级为本地 FAISS/Chroma，接口保持可替换 |
| Embedding | `BAAI/bge-m3`，GPU 推理，`EMBEDDING_VERSION` 记录在 chunk 上 |
| 检索 | dense top_k=20 + BM25 top_k=20 → 去重 → RRF(k=60) → top 15 → reranker → top 5~8 |
| Reranker | `BAAI/bge-reranker-v2-m3`（GPU），支持配置关闭降级 |
| LLM | OpenAI-compatible API（DeepSeek/Qwen/GLM/OpenAI 任一，用户提供 key 入 `.env`） |
| 语料范围（MVP） | 先 20~50 只活跃股票近 1~2 年新闻/公告（AkShare + 巨潮等），全市场二期再扩 |
| Quant 契约 | 量化结果与原系统一致性留版本说明；Agent 调工具只拿结构化结果 |
| 安全 | 工具白名单；Agent 无 SQL/Shell/文件权限；输出带“非投资建议”声明 |

### MVP Definition of Done（文档 §26/§35 摘录）

- 输入“分析贵州茅台”一类问题：自动识别代码 → 调 XGBoost → Hybrid RAG 取新闻/公告 → rerank → LLM 输出带引用和“数据事实/模型结果/推断”区分的报告。
- 每条关键证据可追溯到 metadata；量化结果与原系统一致或有版本说明。
- 有 ≥30 条评测集和对照表；README 可在 5 分钟内让面试官看懂“为什么做、怎么做、难点、如何评测”。
