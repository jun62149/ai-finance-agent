# Issue 1：BM25 后置过滤导致漏召回（最高优先级）

审计发现：

当前：

```
BM25:
全库检索 top200
        ↓
stock_code/doc_type/date过滤
        ↓
返回结果
```

而 Dense：

```
Qdrant:
payload filter
        ↓
过滤后的全量候选中搜索
```

两个候选空间不一致。

真实复现：

```
query='公告'
stock=000333
doc_type=announcement

当前窗口：
2

理论全量过滤：
356
```

请设计修复方案。

重点回答：

简单扩大 BM25 window

例如：

```
200 → 5000
```

优缺点？

性能影响？

109k chunks 数据规模下是否可以接受？

方案 B：
BM25 分片索引

例如：

```
stock_code/doc_type
```

分别建立索引。

是否值得？

方案 C：
替换为 Qdrant sparse vector / BM25 sparse embedding

是否符合当前项目规模？

迁移成本？
